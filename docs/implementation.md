# Implementation decisions

The user approved all remaining phases and confirmed **one production location**. The original Phase 1 document is retained as the proposal; this file records the implemented architecture and deliberate changes.

- React/TypeScript/Vite frontend and Express/TypeScript REST backend share Zod DTOs. React Query owns server state; React Hook Form owns validated forms. Tailwind v4 imports shared semantic CSS tokens; most visual recipes live in the shared stylesheet.
- Microsoft SQL Server is the deployment database, using `node-mssql`, bound parameters and native T-SQL migrations in `migrations/mssql/`. The database adapter normalizes the application's finite shared query forms into SQL Server syntax, including locks, pagination, JSON and dates. Stock constraints, runtime permissions and immutable-history triggers remain directly inspectable. PostgreSQL/PGlite remain explicit legacy development/test backends; configuring SQL Server never falls back to them after a connection error. See `sql-server.md` for setup and migration boundaries.
- Stock entries are represented directly by signed immutable `stock_movements` rows, each tied to one item and the sole production location. A separate multi-entry transfer table is unnecessary for this scope. `stock_balances` is the transactionally updated projection. Quantities are bounded integers (0–1,000,000,000). Pricing remains excluded from forms, public payloads, dashboard, settings and reports. Historical database amounts and immutable snapshots are retained internally; ordinary edits preserve them.
- Categories and supplier names have database foreign keys; Tools and Jigs categories are seeded without changing existing items. The singleton location is constrained to `id = 1`, resolved on the server and unavailable for creation/deletion through the API. Transfers are excluded. The Company details editor remains removed, preserving the existing location name/timezone and fixed Shindengen identity.
- Stock mutations lock item then balance, check a required version, insert the ledger/audit/outbox records, update the projection and store the idempotent response in one transaction. Replayed keys return the original response; different input with the same key returns 409. Serialized movements update unit state and append serial events atomically. Corrections are new ledger entries. Reconciliation is available through the CLI and an Admin endpoint.
- Tool/jig requests reuse the item photos and stock service. Requests move through pending, approved, issued and returned, or become rejected/cancelled before issue. Pending/approved quantities are not reservations. Admins record the actual handover once (possibly fewer than requested), which deducts that amount in the same transaction as request state, history, audit and notifications. Partial returns add stock until all actually issued units are returned. The unissued remainder of a partially fulfilled request requires a new request.
- Staff accounts are request-only: active catalog/photos, own request submission/status/cancellation and own notifications. Direct stock, catalog writes, global history, exports and administrative routes are denied by API and UI. Managers retain catalog/photo/stock management and their own requests; Admins monitor all requests and approve/reject/issue/return. Viewer remains read-only. Request quantities and state versions are validated server-side; concurrent issue/cancel operations serialize on the request and stock locks. Idempotency keys protect creation, issue and return. Serialized returns must belong to that loan, manual restocking cannot bypass loan ownership, and items with outstanding loans cannot be archived.
- In-app notification badges/lists poll every 20 seconds and persist per recipient, with owner-scoped read actions. Admins receive new/cancelled requests; decisions, issues and returns notify the requester and Admins. The same events queue branded transactional email. Browser tests force local mail and a separate data/database configuration to prevent use of an inherited live SMTP/database setting.
- Without a configured database, legacy local evaluation and fast tests use persistent/in-memory PGlite. This fallback is forbidden in production and does not prove multi-connection concurrency. SQL Server URLs select the real SQL Server driver; `TEST_DATABASE_URL` must point to an isolated disposable test database. SQL Server integration exercises the same API contract on the real engine, including request and stock transactions.
- A bounded worker thread processes each image, with a 10-second timeout, JS heap limits, input byte/dimension/pixel limits and at most two concurrent decoders. SVG accepts a deliberately restricted structural/attribute allowlist and rejects external resources, entities, scripts, styles and links. Only re-encoded raster results are stored. Native decoder memory is additionally bounded by the production container memory limit; worker-thread JS limits alone do not isolate native allocations.
- Private object storage uses random keys. Fifteen-minute HMAC-signed, same-origin API URLs keep internal MinIO addresses out of browsers. Login branding is deliberately public company metadata and a raster derivative; stock/images require authenticated access before a signed link is issued.
- Reports and labels are bounded synchronous PDF responses (maximum 2,000 items), not background PDF jobs. CSV exports are capped at 10,000 rows. Narrow filters when limits are exceeded. CSV imports are capped at 1,000 rows/1 MiB, preview before explicit commit, and use savepoints with durable partial-success reports. Commit is repeat-safe. Opening stock must be entered through the ledger, not imported as an untracked quantity.
- Photos are managed on Item detail after the item exists: upload/drop, progress, primary selection, order controls, deletion confirmation and zoom. Item creation/editing return to Inventory and preserve list context. Draft recovery is scoped by account/item in sessionStorage and expires after 24 hours. Route/unload guards protect unsaved item edits.
- A durable database outbox handles password resets, invitations, threshold-crossing low-stock alerts, tool-request notifications and delayed image cleanup. The app process polls with leases, retries/backoff and a terminal failure state. Successful delivery removes bearer tokens from the job payload. Development without SMTP writes private `.eml` files under `.data/mail/`; production requires a real SMTP URL. Email delivery is at-least-once: a crash after SMTP acceptance can produce a duplicate.
- The deployment is intentionally one app instance. Its request limiter and image concurrency gate are process-local. Before adding replicas, use a shared rate-limit store, reassess worker leases/delivery deduplication and test SQL Server concurrency under load.
- Company logo changes propagate to web UI, future email, generated reports and labels. The user subsequently removed Company details editing and fixed the company identity to SHINDENGEN ELECTRIC MFG.CO.,LTD. The shared `COMPANY_NAME` constant supplies the brand resolver and UI fallbacks, so legacy database name overrides cannot change the displayed company. The former details mutation returns 405 for Admins; production-name/timezone records are retained without a settings editor. Admin logo uploads still override canonical bundled files without overwriting approved assets. Previous brand assets remain retained for audit/recovery; deletion/retention policy needs an operator decision. Original Shindengen SVG artwork and the official website favicon mark are now bundled, with provenance recorded in public/brand/README.md. Generated and runtime icons derive from the active mark (SVG or PNG); dark surfaces keep the original blue logo on a white backing plate.
- No currency is shown or entered after pricing removal. The existing display timezone is retained after removal of the Company details form. No SDP acronym expansion or official hex values have been invented. New CSV templates and exports omit monetary columns; older templates' price/cost columns are accepted but ignored, and reviewed pre-update imports remain committable without writing those amounts.
- No remote deployment has been performed. Server access, real DNS/TLS trust and SMTP require installation-specific configuration.
- Final registry checks returned authentication errors for the proposed MinIO image tags. `infra/Dockerfile.minio` therefore builds the official pinned server security release and client release from source. This is a reference S3 service, not a claim of current upstream support: [MinIO server](https://github.com/minio/minio) and [client](https://github.com/minio/mc) are archived. For live deployment, choose a maintained S3 service or establish explicit patch ownership. Follow the official [source-build release instructions](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z); retain upstream licenses included in the reference image.
