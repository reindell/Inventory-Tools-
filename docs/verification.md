Browser journeys cover direct inventory-row edit/archive/restore with retained filters and focus, create/edit, receipt/issue, refusal of negative stock, archive/restore, printable barcode PDF download, search/clear/filter/sort/paging, keyboard focus restoration, loading/error/retry states, retained input after failed stock submission, mobile dark mode without horizontal overflow, Admin logo upload/removal and audit events, no observed client runtime errors, unsaved-edit protection, and IME-safe committed search. Screenshots are under `screenshots/`.

Backend checks cover role denials, CSRF, duplicate identities, final-Admin protection, idempotency replay/mismatch, conflicting concurrent withdrawals, ledger/audit immutability, serial count/ownership/rollback, the singleton location constraint, malicious/spoofed uploads, five-image limit/primary selection, real PDF/CSV generation, import preview/repeat-safe commit, reset-email MIME generation with an embedded logo, one-use reset/invitation tokens, role-change revocation and refresh-token reuse detection.

Native database verification used isolated SQL Server 2022 Express databases with Windows authentication. All 55 backend/adapter/contrast tests passed, including 23 original API tests, 11 request workflow tests, 10 contrast tests, 10 SQL Server adapter tests and one native permission probe. All 13 compiled browser journeys also passed against a separate SQL Server database with generated test credentials and private local test mail. The scratch databases were kept separate from existing inventory databases.

Production limits: Docker/Tedious networking, source-built MinIO, actual S3 networking, real SMTP delivery, Secure cookies behind the final HTTPS proxy, certificate trust, resource sizing and backup restoration remain target-server checks. No remote deployment or automatic transfer of the earlier PostgreSQL data was performed. The default fast tests may use the legacy embedded engine; configured SQL Server connections never fall back to it. Public MinIO registry probes returned authentication errors, so the reference storage container uses pinned official source releases. Review ongoing storage support and patch ownership before live use.

Automated accessibility checks and contrast calculations are evidence, not a complete WCAG conformance assessment. The build emitted harmless upstream Zod annotation warnings; it completed successfully. The original Shindengen logo and website favicon mark are now bundled; application action colors remain provisional. SDP acronym expansion and printer dimensions remain configuration decisions. Pricing and currency entry were subsequently removed at the user's request; historical stored amounts are preserved internally.

Pricing removal regression: item entry/editing, list/detail, dashboard, Settings, CSV and PDF outputs use quantities/status only. API tests verify historical amount preservation and legacy CSV compatibility.

Fixed-company regression: Settings has no Company details editor. API tests verify that Admin company-detail changes are rejected without altering stored settings and that legacy company-name overrides cannot change Shindengen branding. The browser branding journey checks the removed fields, retained Shindengen name, logo upload/removal and audit record.

Bundled-logo regression: the original Shindengen SVG logo and website favicon mark replace provisional artwork. API checks verify bundled metadata and successful raster rendering; browser checks verify loaded login/navigation images, collapsed mark, dark-theme backing plate and restoration after removing a custom upload. Login and Settings screenshots show the bundled artwork. SVG and PNG source provenance is recorded in `../public/brand/README.md`.

Borrowing regression: Staff requests/cancels from a photographed catalog, Admin receives notifications and approves before issuing, a five-unit request can record three actually issued units, partial returns of one then two restore stock, and issued requests cannot be undone by the borrower. API coverage includes cross-account denials, request-only Staff access, cancellation/issue races, concurrent competing issues, stale versions, repeat-safe create/issue/return, serial ownership, blocked manual restocking of borrowed serials and blocked archival while loans remain outstanding. Screenshots: `screenshots/tool-requests-admin.png` and `screenshots/tool-requests-mobile.png`. Automated tests use a test-only larger general request limit to avoid unrelated shared-IP exhaustion; the production limit remains 300 requests/minute.
